# Plan: Index the FuseScope docs

Status: Done
Issue:
PR: https://github.com/fuseone-io/fusescope-mcp-server/pull/5

## Context

The fork's docs tools, `fusescope://docs/sitemap` and the embedded corpus still indexed
signoz.io. FuseScope has its own documentation at
https://fuseone-io.github.io/fusescope-docs/, an Astro Starlight site on GitHub Pages. GitHub
Pages cannot negotiate `Accept: text/markdown`, which is how signoz.io served page Markdown.

## Approach

The docs site publishes `<page>/index.md` and `sitemap.md` at build time
(fuseone-io/fusescope-docs#17). The server treats `https://fuseone-io.github.io/fusescope-docs/`
as the only in-scope docs root, fetches each canonical page from its `index.md`, and keeps the
existing refresh, ETag and indexing paths unchanged.

## Files to Modify

- `internal/docs/types.go` — docs host, base path, root URL and sitemap URL.
- `internal/docs/normalize.go` — canonical URL scope and `MarkdownURL`.
- `internal/docs/fetcher.go` — fetch `MarkdownURL(canonical)`.
- `internal/docs/index.go`, `internal/docs/errors.go` — root URL in path tokens and the out-of-scope message.
- `internal/handler/tools/docs.go`, `pkg/instructions/instructions.go` — client-visible wording and section examples.
- `internal/docs/assets/` — corpus rebuilt from the FuseScope docs (87 pages).
- `internal/docs/testdata/golden_queries.json`, `internal/docs/golden_test.go` — FuseScope golden set and section filters.

## Key Decisions

### 2026-10-31 — Publish Markdown from the docs build

- Decision: the docs site writes `index.md` beside each page and a Markdown sitemap.
- Rationale: keeps runtime refresh working and needs no change to the indexing model.
- Alternatives rejected: reading MDX from the docs repository at build time, which loses runtime refresh and duplicates MDX flattening in Go.

### 2026-10-31 — Re-anchor the golden baseline

- Decision: a new 46-query golden set with baseline ranks measured on the new corpus, and the "at least one overall metric must improve" assertion removed from `TestGoldenSet`.
- Rationale: the improvement rule compares a ranking change with the ranking before it. A new corpus has no earlier ranking, so the rule cannot hold for the first baseline. The per-style tolerances, the keyword floors and "must not decrease" still gate every later change.

### 2026-10-31 — Corpus-size precondition

- Decision: `TestGuardrail_DocsIndexBuildPeakHeap` requires more than 50 pages instead of 500.
- Rationale: the check only proves the test runs on the real corpus rather than the two-page fallback; the FuseScope corpus has 87 pages. The heap budgets are unchanged.
